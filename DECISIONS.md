# Study Carrel: Decisions

Last updated: 2026-10-06

## Concept

A web app for associating text (scripture, poetry, prose) with a **focus**: a question, metaphor, or thesis. The reader sees the passage with the focus pinned prominently, highlights the verse they're pondering, and annotates it as thoughts come.

Example: read Isaiah 40 while pondering "What does it mean to be holy?"

## Decisions made

| Topic | Decision |
|---|---|
| Foci | One focus at a time. No parallel foci in v1. |
| Notes | **One note per verse per focus** (decided 2026-10-03), in an always-open Lexxy editor, docked as a full-height page down the right (a bottom sheet on phones, whose handle shows the note's first line), that **autosaves** as you type (and on leaving the verse); clearing it deletes the note. Enforced by a unique index on `(focus_id, unit_id)`. Trade-off accepted: no per-note timeline of when each thought arrived (only the last-updated time), and last save wins across tabs. Toolbar shrunk (icons about 35% smaller) and moved below the text; on desktop it shows only while the editor has focus (decided 2026-10-05). |
| Users | **A few invited people** (decided 2026-10-02). Foci and notes belong to a user, and nobody (admins included) can read another user's notes; the library is shared. Sign-up is by **invitation only**: an admin creates a single-use link (stored as a digest, shown once, expires in 7 days, open to whoever holds it) and sends it themselves; no email delivery. `users.admin` is set with `bin/rails study_carrel:make_admin EMAIL=...`. No password reset yet. **Sessions last 30 days** from sign-in, then you sign in again (decided 2026-10-04; expired rows are cleared daily), and **Sign out signs you out on every device**. Possible later: encrypting notes. Sharing notes is still manual (copy/paste). |
| Texts | The app ships with a **bundled corpus**. No import or external API in v1. |
| Mobile | Same functionality as desktop. One responsive design, no cut-down phone version. |
| Platform | Web application, usable from laptop and phone. |
| Stack / editor | No preference from the user; Claude decides. **Rails + Hotwire + SQLite** (user OK'd Rails). **Lexxy 1.0.0** for notes (step 9 spike passed), on Action Text. |
| Reading model | **Lectio mode only** for v1: one verse at a time, large, with nothing else from the chapter on screen. Revised 2026-10-05 (the reader felt cluttered): the faded neighbors, the numbered-circle verse strip and the bevelled band behind the verse are gone. Below the passage, `‹ 25 of 31 ›`: the arrows step (naming where they go as a tooltip, and carrying on into the next chapter at an edge), and the number opens a plain grid of every verse (a dot = has a note, a small ribbon = kept). Prose is read a sentence at a time (see Prose by sentence). Full-chapter reading view deferred as a possible future option. |
| Focus presentation | The focus is the hero of the screen: compact and quiet (revised 2026-10-04: a small muted label and a ~20px italic title in soft ink, accent only on hover, because the filled pill and 32px accent title read as a shout), at the top of the reading column (since 2026-10-05; it was a band under the nav), sticky so it stays visible while scrolling, and left-aligned (decided 2026-10-03) so a short focus doesn't get lost in the middle; it lines up with the body text. Prototype feedback: a thin bar felt lost; a large hero banner was too big. Description opens as a dropdown. |
| Text alignment | Left-aligned (ragged right), not centered, and flush with the focus. The text keeps a ~34em measure at every width (revised 2026-10-05). Type size steps down for longer units (long sentences of prose). Demo of long prose: open `prototype/index.html?text=prose`. |
| Design | **Committed** (2026-10-02): `prototype/index.html` is the reference for look and feel: lectio-only, compact sticky focus, left-aligned text with length-adaptive sizing. **Reader revised** (2026-10-05) after five layouts were tried in `prototype/reader/` (A desk, B open book, C single column, D rail and ruler, E rail and steps): **E** was chosen, `prototype/reader/e.html` (D's rail and docked note with A's `‹ 3 of 31 ›`; D's hairline ruler was dropped). |
| Bundled texts | **KJV Old Testament and New Testament** (the NT built the same way, 260 chapters), **Book of Mormon** (Gutenberg #17, older public-domain text, 6,604 verses; labelled "Public-domain text", not the Church's current copyrighted edition), **World Scripture** (Dhammapada, Müller; Tao Te Ching, Legge; Bhagavad Gita, Arnold's *Song Celestial*; Quran, Rodwell in the traditional sura order, whose verse numbers can drift by one from the standard in about two dozen suras), **Marcus Aurelius: Meditations** (Casaubon's 1634 translation), **Robert Frost** (the 1930 Collected Poems, public domain from 2026) and **Edgar Allan Poe** (1900 Bell edition), all from Gutenberg, **KJV Old Testament** (Gutenberg base, cross-checked against two other sources; 115 verses taken from the other sources where the base differed), **Emily Dickinson** (five works, stanza per unit: *Poems* First, Second and Third Series, 442 poems from Gutenberg; *The Single Hound*, 1914, 142 poems, and *Further Poems*, 1929, 181 poems, both from proofread Wikisource transcriptions because Gutenberg lacks them; rebuilt with `script/texts/build_dickinson_later.py`), **Thoreau: Walden** (Gutenberg). **Prose batch 2** (2026-10-04, `script/texts/build_prose.py`, all Gutenberg, single-source): **Pascal, *Pensées*** (#18269, 923 numbered thoughts in 14 sections; the file doesn't name the translator, but it is W. F. Trotter's, so the edition reads "Trotter translation" with no year; T. S. Eliot's introduction and the editor's notes are left out), **Emerson, *Essays*, First Series** (#2944, 12 essays) and **Second Series** (#2945, 9 essays), with the epigraph verse left out, and **Montaigne, *Essays*** (#3600, Cotton's translation as edited by Hazlitt, 1877; 107 chapters, sections labelled "II.3 …" by book and chapter; the Gutenberg volunteers' bracketed notes signed "D.W." are stripped). Single-source texts rely on Gutenberg's proofreading. Rebuild with the scripts in `script/texts/`. The Prose collection is split into sentences when built (see Prose by sentence). |
| Prose by sentence | **Every work in the Prose collection is read a sentence at a time** (decided 2026-10-06; Walden, both series of Emerson's *Essays*, Montaigne, *Meditations*, the *Pensées*), after the prototype showed it was "so much more impactful for the long prose passages" than a paragraph at a time. Prototype: `prototype/reader/sentences.html`. Each sentence is a unit, so notes, keeps, history, search and Random work on sentences unchanged; it also knows its group (a paragraph, Pascal's thought, Marcus's numbered section; `works.group_name`) and its place in it. Units are numbered in reading order through the chapter (`/read/walden/2/112`, "112 of 219"), and cited by group and sentence: "Walden: Economy 12:3", "Meditations: Book 3 12:2" (its books are labelled "Book 3" for this). A group's first sentence opens with a ¶, hung in the left margin (inline on phones). The verse grid has a row per group, and a ¶ button after the arrows (or `p`) shows the whole group with the current sentence marked and each sentence a link. Splitting happens when the texts are built (`script/texts/sentences.py`), so the text files list sentences as `12.3 Text` and a bad split is fixed in a reviewable diff: abbreviations, initials, list numbers and citations in brackets don't end a sentence, a lone "Hermit." or "Ibid." joins its neighbour, and Thoreau's account tables stay whole. Reloading keeps unit ids by matching a sentence's text in its group, then its place: a paragraph loaded before the split became its first sentence, carrying its notes, keeps and history; a row left unmatched is deleted unless something hangs off it. Trade-off accepted: some sentences are still very long (one Montaigne catalogue runs 5,900 characters). |
| User texts | **Users can add their own texts** (decided 2026-10-06; first slice built the same day: adding, the review, reading, search, Random, the Your texts page (`/texts`), and deleting a text with nothing noted or kept in it; not yet: revising, detached notes), first for prose such as journals and transcripts of talks. **Private to the uploader, always**: `works.user_id` (null = bundled), and every lookup goes through one visibility scope (reader, search, Random, Kept, history, export), with tests that another user gets a 404 everywhere. Making a private text public is a manual step for the admin (clear `user_id`, file it in a collection); users can't do it. **Plain text only** (`.txt`/`.md` or pasted), one work per upload, title and author from the form: if a blank line falls between two lines of text, blank lines separate paragraphs and single line breaks are joined, otherwise each line is a paragraph (blank lines around headings don't count, so a journal with one paragraph per line can still space out its headings); a line starting `# ` starts a section and labels it (none means one section); everything else is literal, never rendered as Markdown. Other formats are converted outside the app (the admin helps). Paragraphs are split into sentences as in Prose by sentence (`SentenceSplitter`, a Ruby port of `sentences.py`, tested to split all the bundled prose identically), and **a backslash beside `.` `?` `!` overrides the split** (decided 2026-10-06): `Sgt\. Pepper` is not an ending, `with M.\ We` is, and `\\` is a literal backslash; anywhere else a backslash shows as typed. Markers stay in the stored source, so they survive revisions, but never reach a unit's text. The review lists every marker, says when one changes nothing, and flags a backslash left as typed, the upload is saved directly by `UserText#publish!` (not through `TextLoader`, whose matching by section and paragraph number doesn't suit revisions), and a review screen shows the result before it is published: counts, which paragraph rule applied, a "Worth a look" list (initials that didn't split, short words that did, lines that look like headings, Markdown left as typed, markers), every sentence shaded in turn, and a reader-style preview. Prototype: `prototype/upload.html` (`?revise` for a revision). Uploads go in a per-user "Your texts" at the top of the library (and in the ⋯ menu), with a random slug suffix (`journal-k3f9`) so a URL never reveals another user's titles, are included in search, and are one more branch for Random. Revising replaces the whole source, and the review shows what happens to each note and keep before saving. Matching must be looser than the bundled loader's, which goes by section and paragraph number (adding a heading or a paragraph renumbers everything after it): sections by name, then place; sentences by exact text in their section, then anywhere in the work; each old paragraph is paired with the new one most of its sentences went to, and a leftover sentence matches the most alike one there (a rewording, or one half of a sentence split in two), failing that the one in its place. **Detached notes**: a note whose unit is gone (after a revision, or when a work is deleted) moves to `detached_notes`, keeping its focus (if any), body, citation, work title, the passage text and its original times, plus when and why it was detached; they show after the focus's notes under "From passages that changed or were removed" and are exported. A keep with a remark always becomes a detached note of its own, never merged into a note, since keeps belong to no focus: its focus is blank, and it is shown as a special case at the foot of the Kept page under the same heading (and exported). A keep without a remark is dropped, as are visits. This also makes deleting a work safe, and could later replace the bundled loader's keeping of leftover rows. |
| Library structure | **Collection > Work > Section > Unit** (decided 2026-10-02). Collections are a real table (name, slug, position, description, parent) so they can have their own pages, e.g. "Old Testament". **Collections nest** to any depth (decided 2026-10-02) via `parent_id`: e.g. Sacred Texts > Book of Mormon > 1 Nephi (a Work). A collection's Random and work count include everything nested under it; the library lists top-level collections only. Works have a `position` for canonical order. Loading texts updates in place and never deletes, so notes survive reloads (the one exception: a sentence left over after prose is re-split, if nothing hangs off it; see Prose by sentence). A Bible book is a Work, a chapter a Section, a verse a Unit. |
| Authors | **Optional `works.author` (full name) and `works.author_short`** (decided 2026-10-04), set by `author:` / `author_short:` in the text files; blank for scripture and anything without a known author. Translators stay in `edition`. Library pages show the full name beside the work; lectio shows the short name in the small slot before the edition ("Frost · Collected Poems (1930)"), hidden on phones. Nothing is shown when the title already is the author (Emily Dickinson). |
| Landing page | **Public landing page at `/`** (decided 2026-10-04) for signed-out visitors, using its own layout (`layouts/landing`, CSS inline) so it can't leak into app styles; signed-in users still go straight to reading. Prototype: `prototype/landing.html`. No contact address or email link anywhere, because signups are by invitation only and the author doesn't want to be reachable by strangers. |
| History | **Global per user, not per focus** (decided 2026-10-04), so a trail survives starting a new focus. `visits` table, one row per `(user, unit)`, newest first, capped at 50, written by `PositionsController#update`. Stepping to a neighboring verse moves the latest entry along instead of adding one, so the list holds places, not every verse read. UI: a clock icon (beside the ⋯ menu on library pages, in the rail on the reader) opens a dropdown (on phones it folds into the ⋯ menu as "Recent places" to save room: below 720px on library pages, below 900px on the reader) of the last 8 places before the current one (reference, snippet, age, a dot if the verse has a note in the current focus); `h` opens it, Up/Down move, Enter goes. |
| Keep | **Keep** (decided 2026-10-04) is the bookmark: a per-user mark on a passage, independent of any focus, for something profound you stumble on and want to return to. `keeps` table, one row per `(user, unit)`, with an optional plain-text remark (200 characters). UI: a bookmark ribbon just left of the reference line above the passage (revised the same day from a ribbon hanging off the focus band, which felt disconnected from the text); the whole reference row sticks below the focus while a long passage scrolls. Quiet outline when idle; filled accent when kept. Tap to keep (a brief "Kept · Add a remark · Undo" line follows); tap a kept ribbon for a popover with the remark, Release and "See all kept"; `b` does the same as a tap. Kept verses are marked in the verse grid and in the history list. The **Kept page** (`/kept`, from the reader's rail, the ⋯ menu and the library) lists passages newest first or in reading order, with the remark, and "Start a focus from this" opens the new-focus form with the passage shown and begins reading there. Not yet: a Random scope over kept passages. |
| Random | **Scoped and balanced** (decided 2026-10-05). The library, collection and work pages roll in that page; the reader's ⋯ menu shows "Random · *innermost collection*" (or the work, if it has no collection), and a ▾ beside it lists the other enclosing scopes (the work, each collection out to the top, the whole library). Rolls are **balanced**: at each level they pick evenly among a collection's non-empty child collections and works, treating a single-work collection (the Bible, the Book of Mormon) as one branch that is even by verse inside. In prose a roll lands on any sentence, chosen evenly like a verse (not snapped to a paragraph's start). Every landing stays in history so a chance find can be found again. Tried and dropped the same day: an "Even" weighting option (needless complication), and an "Another" chip in the reader to roll again in the same scope (the label didn't say what it referred to; the menu does the job). Code: `RandomScope`. |
| Search | **Library search** (decided 2026-10-05) over unit text with SQLite FTS5 (`unit_search`, porter stemming, accents ignored), a copy of each unit's body keyed by unit id and refreshed by the loader per section (`bin/rails study_carrel:reindex` rebuilds it). Every word must appear; `"quotes"` make a phrase and a trailing `*` matches a word's beginning; everything else is plain text, never FTS syntax. Results come in **reading order, not relevance**, 50 to a page, with highlighted excerpts and a per-work count list (folded away above 12 works) whose entries narrow the search to that work. `/search`, whole library by default (`?work=` / `?collection=` to narrow); the search page offers the enclosing scopes as chips, and the library, collection and work pages each have a search box scoped to themselves. The boxes read "Find words in Poetry" (not "Search Poetry", which suggested finding a work by title), and the search page's hint says titles aren't searched (2026-10-05). The ⋯ menu has Search, and `/` opens it (or focuses the box). Prose is matched **a sentence at a time** (decided 2026-10-06): every word must be in one sentence, so a result never opens on a sentence that doesn't match, even if words spread across a paragraph go unfound. Left out for now: matching titles and references, and searching notes. Code: `LibrarySearch`. |
| Reading nav | **Minimal** (decided 2026-10-04). **Library, collection, work, search and kept pages** share a top bar (`shared/_header`), with Random scoped to the collection or work and "Continue reading" in the menu: collapsible breadcrumbs (Library › collections › work › chapter, no "Study Carrel" brand) and one ⋯ menu. The first and last crumbs always show; middle ones drop out nearest the root first, leaving a "…"; the work crumb is skipped when the chapter name already starts with it ("Isaiah 40"); edition and author appear only as tooltips. **The reader has no top bar** (decided 2026-10-05; it made the page feel cluttered): a thin icon rail down the left (`readings/_rail`) holds *Where you are* (a popover with the library trail, indented a level per step, and the chapters either side), Recent places, Search, Kept, and the ⋯ menu at the bottom (All notes, All focuses, Random, light/dark, Invitations for admins, Sign out). On phones the rail collapses to a single ⋯ at the top right whose menu takes in the trail and everything else. Both menus render `shared/_menu_items`. The library pages keep their top bar for now. |
| Process | Build a plain-HTML prototype first (`prototype/index.html`) to iterate on look and feel before committing to a stack. |

## Design implications

- The focus is the app's current state: no switcher or lenses. Home is "continue where you left off". Past foci live in a simple archive list.
- Layout is adaptive. Desktop shows text and notes side by side. Phone shows text with a bottom sheet for notes.
- Lectio Mode (one verse at a time, large type) is a reading option on all screen sizes, and a candidate default on phones.
- Notes are a perpetually open editor for the current verse that autosaves; there is no add/expand step.
- Texts need a generic addressable-unit model (work > section > numbered unit) covering verses, poetry lines/stanzas, and prose paragraphs.

## Proposed v1 scope

**In**
1. Bundled texts (2-3 to start), browsable by work and chapter
2. Create a focus (title, optional description) and mark it current
3. Read a passage with the focus pinned on top
4. Set the current verse, which highlights it
5. Write a note on a verse (always-open rich editor, autosaved; one note per verse per focus)
6. See notes in the margin/side panel, and in the mobile bottom sheet
7. Focus view: all notes in reading order
8. Markdown export
9. Responsive layout that works well on a phone

**Later**
- Word-level highlights within a verse
- Cross-reference links (`@Psalm 23:1`) with previews
- "Current answer" document with version history
- Margin Map (minimap of where notes cluster) and Synthesis view
- Offline support / PWA
- Search
- Encrypting notes and user texts at rest (user texts make this more pressing)

## Visual tone (ideas, not decisions)

Quiet study desk, not a productivity tool: serif reading face, warm paper tones, dark mode for night reading, a calm but prominent focus line, and no gamification or streaks.
